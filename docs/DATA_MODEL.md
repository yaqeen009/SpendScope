# Data model

Six tables, all owned by a tenant boundary (`Workspace`). The schema lives in
[`apps/api/prisma/schema.prisma`](../apps/api/prisma/schema.prisma); the SQL is
committed under `apps/api/prisma/migrations`.

## Conventions

| Convention | Rule |
| ---------- | ---- |
| Money | Stored as a **positive magnitude** in `DECIMAL(14,2)` plus an explicit `type`. The database never stores a signed amount. |
| Dates | `transactionDate` and `Budget.month` are UTC `DATE` columns (no time, no timezone) so calendar days never shift. `createdAt`/`updatedAt` are `TIMESTAMP(3)`. |
| Tenancy | Every user-owned row carries `workspaceId`. The MVP seeds one workspace, but every query is already scoped by workspace. |
| Transport | Amounts cross the wire as **decimal strings** (`"1234.50"`), never JSON numbers, so no float rounding occurs in the browser. |
| IDs | UUID v4, generated by the database default (`uuid()`). |
| Time | Instants are UTC everywhere; rendering to a local timezone happens only in the UI. |

## Entity relationships

```text
Workspace 1───* Category
Workspace 1───* Transaction ──? Category        (ON DELETE SET NULL)
Workspace 1───* Transaction ──? ImportBatch     (ON DELETE SET NULL)
Workspace 1───* Budget      ──? Category        (ON DELETE CASCADE)
Workspace 1───* ImportBatch
Workspace 1───1 Settings
```

`Workspace` is the root: deleting a workspace cascades to everything it owns.

## Tables

### `Workspace`

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | uuid | PK |
| `name` | text | Display name |
| `isDemo` | boolean | Default `false` |
| `createdAt`, `updatedAt` | timestamp | |

One default workspace is created on first boot (`ensureWorkspace`) and by the
seed. It is the tenancy boundary that future authentication would bind to.

### `Category`

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | uuid | PK |
| `workspaceId` | uuid | FK → `Workspace`, cascade |
| `name` | text | Unique **per workspace** |
| `kind` | enum | `INCOME` \| `EXPENSE` |
| `color` | text? | Hex colour used in charts |
| `description` | text? | |
| `isDefault` | boolean | `true` for the seeded catalogue |
| `createdAt`, `updatedAt` | timestamp | |

Constraints and indexes:

- `UNIQUE (workspaceId, name)` — `Category_workspaceId_name_key`.
- `INDEX (workspaceId, kind)` — used when listing one kind.

A category's `kind` is immutable once transactions reference it; the API refuses
to reclassify a category that is in use (see [DECISIONS.md](DECISIONS.md)).

### `Transaction`

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | uuid | PK |
| `workspaceId` | uuid | FK → `Workspace`, cascade |
| `transactionDate` | date | UTC calendar day |
| `description` | text | Required |
| `merchant` | text? | As supplied |
| `normalizedMerchant` | text? | Lower-cased, punctuation-stripped |
| `amount` | decimal(14,2) | **Positive magnitude** |
| `type` | enum | `INCOME` \| `EXPENSE` \| `TRANSFER` \| `REFUND` |
| `categoryId` | uuid? | FK → `Category`, `ON DELETE SET NULL` |
| `notes` | text? | |
| `reviewStatus` | enum | `NEEDS_REVIEW` (default) \| `REVIEWED` |
| `importBatchId` | uuid? | FK → `ImportBatch`, `ON DELETE SET NULL` |
| `fingerprint` | text? | SHA-256 duplicate key (see below) |
| `isSample` | boolean | `true` for demo-seed rows |
| `createdAt`, `updatedAt` | timestamp | |

Indexes: `(workspaceId, transactionDate)`, `(workspaceId, categoryId)`,
`(workspaceId, type)`, `(workspaceId, reviewStatus)`,
`(workspaceId, fingerprint)`, `(workspaceId, amount)`, `(importBatchId)`.

The `type` column is what gives the magnitude a direction:

| Type | Meaning | Effect on totals |
| ---- | ------- | ---------------- |
| `INCOME` | Money in | Adds to income |
| `EXPENSE` | Money out | Adds to expenses |
| `REFUND` | Money returned against an expense | **Subtracts** from expenses |
| `TRANSFER` | Movement between your own accounts | **Excluded from every total** |

### `Budget`

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | uuid | PK |
| `workspaceId` | uuid | FK → `Workspace`, cascade |
| `month` | date | Always the **first day** of the budget month |
| `amount` | decimal(14,2) | Must be > 0 |
| `categoryId` | uuid? | `NULL` = the single total monthly expense budget |
| `createdAt`, `updatedAt` | timestamp | |

Constraints:

- `UNIQUE (workspaceId, month, categoryId)` — one budget per category per month.
- `UNIQUE INDEX (workspaceId, month) WHERE categoryId IS NULL` — the partial
  index `Budget_workspaceId_month_total_key`, created by migration
  `20261016234000_budget_total_unique`. A plain unique constraint cannot enforce
  this because PostgreSQL treats `NULL`s as distinct; the partial index makes
  the "one total budget per month" rule a database invariant rather than an
  application convention.

### `ImportBatch`

Audit record for each CSV import.

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | uuid | PK |
| `workspaceId` | uuid | FK → `Workspace`, cascade |
| `filename` | text | Sanitised (basename, unsafe characters replaced) |
| `status` | enum | `COMPLETED` \| `PARTIAL` \| `FAILED` |
| `totalRows`, `createdRows`, `duplicateRows`, `invalidRows`, `skippedRows` | int | Row accounting |
| `source` | text | `csv`, `manual` or `seed` |
| `notes` | text? | |
| `createdAt`, `completedAt` | timestamp | |

Index: `(workspaceId, createdAt)` for the import history list.

### `Settings`

Single-row table (`id = 1`, `workspaceId` unique).

| Column | Type | Default | Notes |
| ------ | ---- | ------- | ----- |
| `currency` | text | `GHS` | **Display-only** — never converts amounts |
| `locale` | text | `en-GH` | Number/date formatting |
| `theme` | text | `system` | `light` \| `dark` \| `system` |
| `defaultPeriod` | text | `this_month` | Analytics default range |
| `updatedAt` | timestamp | | |

## Duplicate detection

Duplicate detection is **heuristic** and fingerprint-based. The fingerprint is
the SHA-256 hash of:

```text
transactionDate | normalised description | amount | TYPE | normalised merchant
```

Normalisation lower-cases, strips diacritics, removes punctuation and collapses
whitespace.

- **Exact duplicate** — the fingerprint already exists in the workspace (or
  earlier in the same file). Skipped by default; the user can override.
- **Possible duplicate** — same date and same amount but different wording.
  Flagged for the user to decide. The scan is capped at 20,000 rows in the
  affected date range; when the cap is hit the preview carries a warning.

It deliberately does **not** treat two identical legitimate purchases (same day,
same wording, same amount) as duplicates — both are kept and neither is flagged.

## Sample vs. real data

Demo rows are marked `isSample = true` and belong to the same workspace as real
data. That lets the app distinguish "seeded sample data" from "data you
imported" without a second database, and it is what makes
"clear sample data" (`POST /api/v1/settings/demo-data` with `action: "clear"`)
safe: it deletes only `isSample` rows.
